СЛАЙД 6
На основе требований о работе приложения в условиях запрета на установку дополнительного ПО, было принято решение о создании клиент серверного веб приложения.
API приложение является посредником между клиентом и базой данных предоставляя удобное API для клиента. Клиентом является одностраничное приложение статические файлы которого доставляются веб сервером. Сервер электронной почты служит для рассылки данных аутентификации новым сотрудникам.

СЛАЙД 7
На данном слайде вы можете наблюдать диаграмму демонстрирующую ФУНКЦИОНАЛЬНЫЕ ВОЗМОЖНОСТИ. Собственно в системе выделено 2 основные роли: сотрудник и работник отдела кадров. Каждый сотрудник должен иметь возможность создать, сохранить в черновик, отправить уведомление, просмотреть список отправленных уведомлений, а также просмотреть и отреагировать на полученные им уведомления. А работник отдела кадров регистрировать в системе новых сотрудников и изменять их информацию.

СЛАЙД 8
На данном слайде вы можете видеть диаграмму базы данных. Центральными объектами в базе являются таблицы employees и notifications хранящими данные о пользователях и уведомлениях соответственно. Дополнительные данные об уведомлениях хранят таблицы recipients и buttons. Стоит отметить, что таблица notification хранит данные обо всех уведомлениях, не важно являются они черновиками или отправлены. При отправлении уведомления в таблице sended_notification хранятся id уведомления, отправителя и получателя. Positions хранит список возможных должностей. Notification_types все возможные типы уведомлений.


СЛАЙД 9
Основой приложения на express.js являются маршруты(router) и промежуточные функции(middleware). Маршруты позволяют определить как приложение будет реагировать на забросы по тем или иным путям. К каждому из путей будет привязан список из промежуточных функций, занимающихся обработкой запроса. На данном слайде вы можете наблюдать все возможные пути, что они принимают, что возвращают и для чего используются. 

СЛАЙД 10
Клиентская часть приложения реализована с использованием фреймворка vue.js. Данный фреймворк используется для создания пользовательских интерфейсов и предоставляет удобный способ их описания в виде компонентов.
Vuex – библиотека предоставляющая возможность создания централизованного хранилища доступ к которому будет доступен в любом компоненте.
Для взаимодействия с API используется библиотека axios предоставляющая расширенные возможности для описания запросов.
Компоненты отображают данные из хранилища. Хранилища служат для обработки данных. Для получения данных хранилища обращаются к объекту API, который построен на базе библиотеки axios.
